# LK005: tuning-on-test-set

**Severity:** error | **Default confidence:** high (medium for some indirect cases)

## What it detects

The test set steers training or model selection: `eval_set` / `validation_data` / `valid_sets` passed to `fit` with test data (early stopping in XGBoost, LightGBM, Keras and others), a `GridSearchCV` / `RandomizedSearchCV` fitted on test data, or an Optuna-style objective that scores the test set.

## Why it leaks

Early stopping and hyperparameter search pick the setting that does best on the data they look at. If that data is the test set, the reported score is the best of many tries and is biased upward. The test set has become a validation set, and nothing is left to give an honest estimate.

## Bad

```python
model = XGBClassifier(early_stopping_rounds=20)
model.fit(X_train, y_train, eval_set=[(X_test, y_test)])   # LK005
print(model.score(X_test, y_test))
```

## Good

```python
X_tr, X_val, y_tr, y_val = train_test_split(X_train, y_train, random_state=0)
model.fit(X_tr, y_tr, eval_set=[(X_val, y_val)])
print(model.score(X_test, y_test))   # touched once, at the end
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- Keyword names such as `eval_set` are matched by name. A library that uses them for something harmless could cause a false positive.
- Indirect use (test data passed into a helper that then tunes) is not followed, so those cases are missed.
- If the variable called `test` is really a validation split in a three-way split, rename it or suppress.

## Suppress

On the flagged line:

```python
model.fit(X_train, y_train, eval_set=[(X_test, y_test)])  # leakray: ignore[LK005]
```

For a whole file, add `# leakray: ignore-file[LK005]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK005"]` under `[tool.leakray]` in `pyproject.toml`.
