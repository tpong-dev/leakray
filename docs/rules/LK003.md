# LK003: target-in-features

**Severity:** error | **Default confidence:** high

## What it detects

The target column is still inside the feature matrix passed to `fit`. leakray follows the `y` argument back to a column such as `df["target"]` (a string, or a constant like `TARGET = "churn"`) and checks whether the `X` argument was derived from the same frame without dropping or popping that column. Feature lists are resolved too: `df[features]` is reported when the list (or `df.columns`, or a comprehension that does not exclude the target) still holds the target, unless it is removed with `.remove()` / `.pop()`. `select_dtypes` that keeps numeric columns is reported at medium confidence, since the target may not be numeric.

## Why it leaks

The model is given the answer. It reads the target from its own copy and the score is near perfect, but at prediction time the column does not exist. This is the most obvious leak and easy to introduce, for example by building `X = df` after cleaning.

## Bad

```python
df = pd.read_csv("churn.csv")
X = df                      # still contains "churn"
y = df["churn"]
model.fit(X, y)             # LK003
```

## Good

```python
df = pd.read_csv("churn.csv")
X = df.drop(columns=["churn"])
y = df["churn"]
model.fit(X, y)
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- The target is recognised from how `y` is built out of a column name or constant. If `y` comes from a function call or another file, the rule stays silent.
- `select_dtypes` findings are medium confidence because leakray cannot see the target's dtype.
- Columns that are a copy or close proxy of the target (`churn_date`, `churn_flag`) cannot be seen, because that needs data values.
- If the column is removed through a path leakray does not follow (a helper function, a computed column list), a false positive is possible.

## Suppress

On the flagged line:

```python
model.fit(X, y)  # leakray: ignore[LK003]
```

For a whole file, add `# leakray: ignore-file[LK003]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK003"]` under `[tool.leakray]` in `pyproject.toml`.
