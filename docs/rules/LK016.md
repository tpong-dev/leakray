# LK016: concat-train-test-before-fit

**Severity:** error | **Default confidence:** high

## What it detects

Train and test frames are combined with `pd.concat` and the combined data is then used to fit preprocessing (scalers, imputers, encoders, `CountVectorizer`, `LabelEncoder`) or to compute statistics such as `.mean()` and `.median()`.

## Why it leaks

Concatenating train and test to "keep the columns aligned" is a common pattern in competition notebooks. It makes the transformer learn from the test set (scaling statistics, vocabulary, category lists), so the model is evaluated with test information already baked in.

## Bad

```python
full = pd.concat([train, test])
full["age"] = full["age"].fillna(full["age"].median())     # LK016
enc = OneHotEncoder().fit(full[["city"]])
```

## Good

```python
enc = OneHotEncoder(handle_unknown="ignore").fit(train[["city"]])
train_enc = enc.transform(train[["city"]])
test_enc = enc.transform(test[["city"]])
train["age"] = train["age"].fillna(train["age"].median())
test["age"] = test["age"].fillna(train["age"].median())
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- Concatenating only to apply stateless changes (renaming columns, parsing dates) and then splitting again is fine, but is reported if a fit follows on the combined frame.
- Using unlabeled test features for unsupervised encoding is a known trade-off in some competitions; the rule still reports it, and you can suppress it knowingly.
- Concatenation done in a helper function is not followed.

## Suppress

On the flagged line:

```python
full["age"] = full["age"].fillna(full["age"].median())  # leakray: ignore[LK016]
```

For a whole file, add `# leakray: ignore-file[LK016]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK016"]` under `[tool.leakray]` in `pyproject.toml`.
