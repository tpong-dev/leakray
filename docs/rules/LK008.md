# LK008: target-encoding-on-full-data

**Severity:** error | **Default confidence:** high (medium when the target is only a name hint)

## What it detects

A target or mean encoding computed on the full data before the split: `df.groupby(cat)[target].mean()` or `.transform("mean")` mapped back onto the frame, or a target encoder fitted on all rows.

## Why it leaks

Each row's encoded value then includes its own label (and test labels) in the category average. For rare categories the encoding is almost the label itself. The model learns the shortcut and the validation score is inflated, while new data has no such shortcut.

## Bad

```python
means = df.groupby("city")["price"].mean()
df["city_enc"] = df["city"].map(means)                 # LK008
X_train, X_test, y_train, y_test = train_test_split(df.drop(columns=["price"]), df["price"])
```

## Good

```python
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=0)

from sklearn.preprocessing import TargetEncoder
from sklearn.pipeline import make_pipeline
model = make_pipeline(TargetEncoder(), Ridge())
model.fit(X_train, y_train)
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- The target is found by name hints (`target`, `label`, `y`, the column used for `y`). An unusually named target is missed.
- A groupby mean over a column that is not the target is not reported here (see [LK014](LK014.md)).
- Leave-one-out or out-of-fold encodings coded by hand are not recognised as safe and may be reported.

## Suppress

On the flagged line:

```python
df["city_enc"] = df["city"].map(means)  # leakray: ignore[LK008]
```

For a whole file, add `# leakray: ignore-file[LK008]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK008"]` under `[tool.leakray]` in `pyproject.toml`.
