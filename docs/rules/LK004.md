# LK004: fit-on-test-data

**Severity:** error | **Default confidence:** high

## What it detects

A model or transformer's `fit`, `fit_transform` or `partial_fit` is called with data that leakray believes is the test set (a variable from a split output, or one named like `X_test` / `test_df`). Cross-validation fold variables inside a loop are excluded.

## Why it leaks

Once the test set is used for fitting, it is no longer unseen. A scaler fitted on test data hides a distribution shift. A model fitted on test data memorises it, so the test score says nothing about new data.

## Bad

```python
scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)
X_test = scaler.fit_transform(X_test)     # LK004: refits on test
```

## Good

```python
scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)
X_test = scaler.transform(X_test)
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- A variable is treated as test data by its role or name. A variable named `test` that holds a second training source is reported.
- Intentional unsupervised refits on unlabeled test data (domain adaptation, transductive methods) are a leak only if test labels are used for evaluation; leakray cannot tell the difference. Suppress with a comment.
- Test data reaching `fit` through a list, dict or function return is not tracked.

## Suppress

On the flagged line:

```python
X_test = scaler.fit_transform(X_test)  # leakray: ignore[LK004]
```

For a whole file, add `# leakray: ignore-file[LK004]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK004"]` under `[tool.leakray]` in `pyproject.toml`.
