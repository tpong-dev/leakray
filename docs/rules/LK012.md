# LK012: kfold-ignores-groups

**Severity:** warning | **Default confidence:** medium (low when the id column is a weak hint)

## What it detects

A random `train_test_split`, `KFold`, `StratifiedKFold` or shuffle split is used while the data has a column that looks like an entity id (`patient_id`, `user_id`, `customer_id` and similar), so the same entity can appear in both train and test. Splitter objects passed as `cv=` (for example `cross_val_score(..., cv=KFold(5, shuffle=True))`) are flagged too. Any `Group*` splitter or `groups=` argument in the file silences the rule.

## Why it leaks

Rows of the same patient, user or device resemble each other. The model can learn to recognise the entity and not the pattern, and it scores well on test rows of entities it already saw. Real use is on new entities, where the score is lower.

## Bad

```python
df = pd.read_csv("visits.csv")     # has patient_id
X_train, X_test, y_train, y_test = train_test_split(X, y)   # LK012
```

## Good

```python
from sklearn.model_selection import GroupKFold
cv = GroupKFold(n_splits=5)
scores = cross_val_score(model, X, y, groups=df["patient_id"], cv=cv)
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- The rule works from column names. A `user_id` column that is unique per row is not a group, and the finding is a false positive.
- Group structure with no id-like column name (a `source` or `site` column) is not detected.
- A strong entity name (`patient_id`, `user_id`) gives medium confidence; a generic `*_id` column gives only low confidence; use `--min-confidence medium` to filter.

## Suppress

On the flagged line:

```python
X_train, X_test, y_train, y_test = train_test_split(X, y)  # leakray: ignore[LK012]
```

For a whole file, add `# leakray: ignore-file[LK012]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK012"]` under `[tool.leakray]` in `pyproject.toml`.
