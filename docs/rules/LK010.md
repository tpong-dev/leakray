# LK010: unshifted-target-lag-feature

**Severity:** error | **Default confidence:** high (medium when the target is only a name hint)

## What it detects

A rolling, expanding, `ewm`, `diff`, `pct_change` or cumulative feature is computed from the target column without a `.shift()`, for example `df["sales"].rolling(7).mean()`.

## Why it leaks

A rolling window that ends at the current row includes the current target value. The feature is partly the answer for that row. The model uses it to "predict" the number it was given, and the score collapses when the feature can only be built from the past.

## Bad

```python
df["sales_ma7"] = df["sales"].rolling(7).mean()       # LK010: includes today
X = df[["sales_ma7", "price"]]
y = df["sales"]
```

## Good

```python
df["sales_ma7"] = df["sales"].shift(1).rolling(7).mean()   # past values only
X = df[["sales_ma7", "price"]]
y = df["sales"]
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- The target is the column the file uses as the label; if none is visible, name hints give medium confidence. Building the target itself (`y = df["price"].pct_change()`) is not reported.
- If the target is later shifted (for example `y = df["sales"].shift(-1)`), the feature can be safe, but leakray may still report it.
- leakray accepts a `.shift()` anywhere in the chain but cannot check its sign or size.
- Lag features of non-target columns are not reported, even when they leak for other reasons.

## Suppress

On the flagged line:

```python
df["sales_ma7"] = df["sales"].rolling(7).mean()  # leakray: ignore[LK010]
```

For a whole file, add `# leakray: ignore-file[LK010]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK010"]` under `[tool.leakray]` in `pyproject.toml`.
