# LK013: repeated-test-evaluation

**Severity:** warning | **Default confidence:** medium

## What it detects

The test set is scored (`score`, `predict`, a metric function) inside a loop over models, hyperparameters or seeds, and the best result is selected inside the loop or right after it (a `best*` variable, `max`, `argmax`, `sorted`, `sort_values`). Per-fold scoring inside a CV loop is not reported.

## Why it leaks

Each look at the test set is another chance to find a lucky setting. After many tries the best test score is optimistic even if every single evaluation was valid. The test set has turned into a selection set.

## Bad

```python
best = 0
for C in [0.01, 0.1, 1, 10]:
    clf = LogisticRegression(C=C).fit(X_train, y_train)
    acc = clf.score(X_test, y_test)          # LK013
    best = max(best, acc)
```

## Good

```python
cv_scores = {}
for C in [0.01, 0.1, 1, 10]:
    clf = LogisticRegression(C=C)
    cv_scores[C] = cross_val_score(clf, X_train, y_train, cv=5).mean()
best_C = max(cv_scores, key=cv_scores.get)
final = LogisticRegression(C=best_C).fit(X_train, y_train)
print(final.score(X_test, y_test))        # once
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- A loop that scores the test set but never selects a best result is not reported; selection far after the loop, or in another function, is missed.
- Scoring a validation set in a loop is fine, but a variable named like the test set will be reported.
- Test evaluation repeated across function calls rather than a loop is not detected.

## Suppress

On the flagged line:

```python
    acc = clf.score(X_test, y_test)  # leakray: ignore[LK013]
```

For a whole file, add `# leakray: ignore-file[LK013]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK013"]` under `[tool.leakray]` in `pyproject.toml`.
