# LK009: global-fillna-before-split

**Severity:** warning | **Default confidence:** medium

## What it detects

Missing values are filled with a statistic of the whole frame (`df.fillna(df.mean())`, median, mode, quantile and so on) while the split comes later in the file.

## Why it leaks

The fill value is computed from test rows too. The leak is usually small, because a mean is a weak summary, but it is real, grows with missing data and small samples, and breaks the rule that the test set must not influence anything done to training data.

## Bad

```python
df = df.fillna(df.mean(numeric_only=True))        # LK009
X_train, X_test, y_train, y_test = train_test_split(X, y)
```

## Good

```python
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=0)
X_train = X_train.fillna(X_train.mean())
X_test = X_test.fillna(X_train.mean())     # training statistic

# or: make_pipeline(SimpleImputer(strategy="mean"), model)
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- Filling with a constant (`fillna(0)`) is not reported because it learns nothing from the data.
- The warning level and medium confidence reflect that the effect is often tiny; for a time series the same fill uses future values, which is worse.
- Filling a frame that is already split, under a name leakray does not recognise (`data1`, `data2`), may be reported.

## Suppress

On the flagged line:

```python
df = df.fillna(df.mean(numeric_only=True))  # leakray: ignore[LK009]
```

For a whole file, add `# leakray: ignore-file[LK009]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK009"]` under `[tool.leakray]` in `pyproject.toml`.
