# LK015: no-dedup-before-random-split

**Severity:** info | **Default confidence:** low

## What it detects

A random split (`train_test_split`, shuffled K-fold) is used and no `drop_duplicates()` call appears earlier in the file.

## Why it leaks

If the data contains repeated rows, a random split puts copies of the same row in train and in test. The model is then tested on rows it has memorised. Scraped, merged or logged data often has duplicates without anyone knowing.

## Bad

```python
df = pd.read_csv("reviews.csv")
X_train, X_test, y_train, y_test = train_test_split(df["text"], df["label"])   # LK015
```

## Good

```python
df = pd.read_csv("reviews.csv").drop_duplicates()
X_train, X_test, y_train, y_test = train_test_split(df["text"], df["label"], random_state=0)
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- The rule cannot see the data. If there are no duplicates the finding is noise, which is why it is `info` severity with low confidence and is hidden by `--min-confidence medium`.
- Near-duplicates (resized images, reworded texts) are not caught by `drop_duplicates()` anyway.
- Deduplication done in another file or another way (a SQL `DISTINCT`) is not seen.

## Suppress

On the flagged line:

```python
X_train, X_test, y_train, y_test = train_test_split(df["text"], df["label"])  # leakray: ignore[LK015]
```

For a whole file, add `# leakray: ignore-file[LK015]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK015"]` under `[tool.leakray]` in `pyproject.toml`.
