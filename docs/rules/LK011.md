# LK011: preprocessing-outside-cv-pipeline

**Severity:** error | **Default confidence:** high

## What it detects

Preprocessing is fitted on the full data, and the result is then passed to `cross_val_score`, `cross_validate`, `GridSearchCV` or a manual CV loop, instead of putting the preprocessing inside a Pipeline.

## Why it leaks

Each CV fold's validation part was already seen when the scaler or imputer was fitted. This is [LK001](LK001.md) for cross-validation, and it makes every fold score optimistic, which also biases a hyperparameter search that relies on those scores.

## Bad

```python
X_scaled = StandardScaler().fit_transform(X)             # LK011
scores = cross_val_score(model, X_scaled, y, cv=5)
```

## Good

```python
pipe = make_pipeline(StandardScaler(), model)
scores = cross_val_score(pipe, X, y, cv=5)
```

## When it can be wrong

leakray reads names and syntax; it does not run your code or see your data.

- Stateless preprocessing (for example a log transform) leaks nothing. leakray only reports estimators that learn from data, but a custom class sharing a name with one of them is reported.
- If a fitted transformer touches only columns unrelated to the model input, the leak may be nil; leakray cannot tell.
- If both LK001 and LK011 apply (split and CV in the same file), you may see both findings.

## Suppress

On the flagged line:

```python
X_scaled = StandardScaler().fit_transform(X)  # leakray: ignore[LK011]
```

For a whole file, add `# leakray: ignore-file[LK011]` anywhere in it. To turn the rule off for a project, use `ignore = ["LK011"]` under `[tool.leakray]` in `pyproject.toml`.
